# Initial threat model

| Threat                                   | Primary control                                                                                                                                                          | Verification                                    |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------- |
| Prompt injection / fabricated AI finding | Treat document content as data; fixed instructions; strict output schema; stable source-block citation verifier; no tools/keys                                           | Adversarial corpus and citation tests           |
| False PASS / FAIL                        | Deterministic-first rules, mandatory-evidence gate, policy thresholds, challenge and resolver                                                                            | Golden evals, boundary tests, human review rate |
| Evidence/agreement substitution          | Content hash, append-only accepted version, locked ordered manifest/root, signed payload root match                                                                      | Tamper and root mismatch tests                  |
| Signer compromise / replay               | Meaningfully isolated key outside ordinary app-secret scope, role separation, EIP-712 domain, nonce, expiry, evidenceRoot/policyHash binding, emergency revocation/pause | Access, replay, revocation drills               |
| Double/over settlement                   | Contract state machine, CEI/SafeERC20, per-obligation accounting                                                                                                         | Fuzz/invariant/state-machine tests              |
| Malicious upload                         | File-size/type/content validation, object quarantine, malware scan, safe parser/OCR worker, no rendering in privileged context                                           | Malformed/polyglot/zip-bomb tests               |
| Privacy or BOLA                          | Organisation-scoped authorisation at every record/object route; opaque keys; short-lived URLs; audit                                                                     | Access-control integration tests                |
| Role/admin abuse                         | Least privilege, separate resolver/adjudicator/admin roles, immutable audit events, pause                                                                                | Permission matrix tests                         |
| RPC/reorg/preconfirmation failure        | Canonical receipt/log reconciliation, confirmation policy, idempotent indexer, secondary RPC                                                                             | Provider outage and duplicate-event tests       |
| Frontend transaction manipulation        | Reconstruct/display contract call from server-authorised intent; wallet chain/address/amount confirmation; typed ABI                                                     | E2E altered-request tests                       |
| Dependency compromise                    | Lockfile, pinned contracts/compiler, Dependabot/OSV/SCA, minimal dependencies                                                                                            | CI vulnerability scan                           |

Assumption: V1 handles only synthetic or explicitly authorised documents and Testnet funds. Mainnet requires an independent security assessment, legal/compliance design, signing custody review and operational controls.
