# Architecture decisions

| ID      | Status                        | Decision                                                                                                                                                                   | Rationale                                                                                                                                                                                                                                                              |
| ------- | ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ADR-001 | Proposed                      | Modular TypeScript monolith, not microservices or a broad monorepo.                                                                                                        | One deployed app with explicit domain modules is fastest to build, test and audit before 2026-08-21.                                                                                                                                                                   |
| ADR-002 | Proposed                      | Next.js App Router + TypeScript for the web/BFF.                                                                                                                           | Mature full-stack React path; keeps authenticated UI and narrow server endpoints together.                                                                                                                                                                             |
| ADR-003 | Proposed                      | PostgreSQL + Prisma 7 and private S3-compatible storage; the job interface remains abstract through Phase 1.                                                               | Relational version/audit data and portable storage. A durable execution model is selected only before Phase 4 after measuring processing duration and deployment constraints; Vercel is not assumed to host a continuously running worker.                             |
| ADR-004 | Proposed                      | Files are quarantined, scanned and text-extracted before semantic evaluation.                                                                                              | Uploaded content is untrusted and never enters privileged prompts or execution paths directly.                                                                                                                                                                         |
| ADR-005 | Proposed                      | Deterministic policy engine is pure, versioned application code; LLM emits schema-validated evidence findings only.                                                        | Prevents AI from interpreting executable policy or controlling payment.                                                                                                                                                                                                |
| ADR-006 | Proposed                      | One small non-upgradeable USD₮0 ERC-20 escrow contract; Foundry tests; OpenZeppelin Contracts pinned to an audited v5 release.                                             | Narrow state machine and least onchain surface. V1 uses official X Layer Testnet USD₮0 only after runtime verification.                                                                                                                                                |
| ADR-007 | Proposed                      | wagmi + viem for browser wallet flow; configure Builder Code `dataSuffix` for application-originated calldata after a code is issued.                                      | Typed EVM client; official Builder Code docs support EOAs but not ERC-4337 UserOperations.                                                                                                                                                                             |
| ADR-008 | Needs decision                | Testnet payment token is configuration, not source code.                                                                                                                   | Official X Layer docs confirm Testnet OKB but do not list a Testnet stablecoin address.                                                                                                                                                                                |
| ADR-009 | Needs decision before Phase 2 | A meaningfully isolated adjudication signing design with narrow EIP-712 authority, nonce/expiry, evidenceRoot/policyHash binding, emergency revocation and contract pause. | The key must never be stored in the ordinary Next.js/Vercel application secret scope. Custody/runtime is unresolved, but ordinary app-secret co-location is rejected.                                                                                                  |
| ADR-011 | Proposed                      | Onchain contract state and canonical transaction receipts/events are settlement truth; database settlement records are projections only.                                   | Prevents the app database from independently declaring economic finality.                                                                                                                                                                                              |
| ADR-012 | Proposed                      | Automated outcomes have no discretionary split.                                                                                                                            | PASS may release the authorised amount; split settlement is resolver-only after a dispute.                                                                                                                                                                             |
| ADR-013 | Proposed                      | Challenge duration is fixed on acceptance and contract-bounded.                                                                                                            | Prevents silent post-acceptance changes; normal fixture is 24 hours and shortened demo durations must be conspicuously labelled.                                                                                                                                       |
| ADR-014 | BLOCKED                       | Do not implement a funded-obligation liveness/escape transition without explicit product approval.                                                                         | The brief defines no immutable evidence/adjudication deadline or safe funded-funds exit. Without one, evidence non-submission, signer outage or resolver outage can lock buyer funds indefinitely; an unbounded admin escape or unilateral arbitrary refund is unsafe. |
| ADR-010 | Proposed                      | No RAG/vector database in V1.                                                                                                                                              | Each adjudication operates only on the locked agreement/evidence bundle; retrieval would add unneeded ambiguity and data exposure.                                                                                                                                     |

Decision status remains Proposed until Phase 1 approval, except product constraints inherited from the source brief.

| ADR-015 | Accepted | Funded-no-evidence refund and threshold GenLayer attestation boundary. | Evidence timeout is immutable at acceptance and starts at funding; it refunds only buyer when no evidence exists. X Layer cannot query GenLayer, so two current attestors must bind an exact result after verifying transaction finality and a matching resolved Tolerance case/result. This remains a threshold trusted bridge, not a trustless bridge. |
| ADR-016 | Accepted | Freeze current GenLayer work to Studionet. | Phase 2C/2D use Studionet only. Bradbury is deferred until explicit approval. Vendor chain metadata is imported centrally from `genlayer-js/chains`. |
| ADR-017 | Accepted | Write-once GenLayer case and versioned atomic result digest. | The deployment submitter may submit but cannot choose a verdict. Consensus writes immutable `ResolvedCaseV1`; Phase 2D hashes its exact atomic fields with the documented ABI encoding. |
